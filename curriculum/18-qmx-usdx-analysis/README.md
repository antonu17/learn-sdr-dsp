# 18. Архитектурный разбор QMX/uSDX

[← Предыдущая часть](../17-python-hf-transceiver/README.md) · [Карта курса](../../README.md)

Статус: roadmap. Уроки и исполняемые эксперименты предстоит добавить.

## Цель

Читать реальные схемы и firmware, объяснять выбор архитектуры и её компромиссы.

**Предпосылки:** 10–17; HDL-практика полезна, но не обязательна для первого анализа.

## Будущие уроки

1. Зафиксировать конкретные hardware revision и firmware version каждого устройства.
2. По первичным источникам восстановить RX/TX block diagrams, Fs, widths и границы analog/digital.
3. Сопоставить методы модуляции, MCU/FPGA workload, ADC/DAC или альтернативные выходные тракты.
4. Исследовать применимые к выбранной версии решения: polar paths, switched PA, фильтрация и feedback.
5. Сравнить измеримые ограничения с собственной Python-моделью и требованиями к трансиверу.

## Python-лаба

- Создать карточку источников: официальный документ/репозиторий, версия, дата, страница или файл/строка.
- Перенести один подтверждённый архитектурный приём в Python и воспроизвести его компромисс.
- Составить сравнительную таблицу QMX/uSDX/своего проекта; неизвестные параметры пометить явно.

Основной стек: NumPy, SciPy / scipy.signal, Matplotlib. Для каждого эксперимента сохраняем параметры, графики с единицами и короткий вывод. До части 14 используем float64 и complex128, кроме явно выделенных опытов с quantization.

## Критерии готовности

- [ ] Отделяю подтверждённые сведения от гипотез и не смешиваю версии устройств.
- [ ] Могу ответить, почему выбраны эти Fs, widths, filters и метод TX, и предложить альтернативу с оценкой цены.
- [ ] Могу предсказать результат ключевого эксперимента до запуска и объяснить отличие от прогноза.

## Результат для общего проекта

Архитектурный обзор с источниками и требования к собственной HF-конструкции.
